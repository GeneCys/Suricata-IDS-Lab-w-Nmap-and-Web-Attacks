# Suricata-IDS-Lab-w-Nmap-and-Web-Attacks
Host-based intrusion detection using **Suricata IDS** on a Linux VM, simulating network attacks from a client VM and capture alerts generated by Suricata

## Overview

This lab demonstrates host-based intrusion detection using **Suricata IDS** on a Linux VM.
You will simulate network attacks from a client VM and capture alerts generated by Suricata. This provides hands-on experience with **SOC operations**, network monitoring, and threat detection.

---

## Learning Objectives

- Install and configure Suricata on a Linux VM
- Monitor traffic on a host-only network interface
- Generate network scans and web attacks from a client VM
- Capture and analyze Suricata alerts (`eve.json`)
- Understand mapping between detected network events and SOC alerts

---

## Lab Setup

| VM | IP Address | Installed Tools | Purpose |
|----|------------|----------------|---------|
| Server / IDS | 192.168.56.101 | Suricata, Nginx | Monitor traffic and generate alerts |
| Client / Attack VM | 192.168.56.102 | Nmap, curl | Generate test traffic and attacks |

**Network:** Host-only (192.168.56.x)

---

## Step-by-Step Instructions

### 1. Configure Suricata

1. Edit `/etc/suricata/suricata.yaml` and set the interface under `af-packet:` to your host-only NIC:

```yaml
af-packet:
- interface: enp0s3
threads: auto
cluster-id: 99
cluster-type: cluster_flow
defrag: yes
````

2. Comment out or remove any pcap: blocks entirely.
3. Restart Suricata.
```` bash
sudo systemctl restart suricata
sudo systemstl status suricata
````

### 2. Generate Traffic from Client VM
```` bash
# Nmap SYN scan
sudo nmap -sS -Pn 192.168.56.101

# Aggressive scan with OS detection
sudo nmap -A 192.168.56.101

# Web attack simulation
curl "http://192.168.56.101/?id=' OR 1=1 --"
curl http://192.168.56.101/../../etc/passwd
````
### 3. Monitor Suricata Alerts
```` bash
sudo tail -f /log/suricata/eve.json
# OR
sudo less /var/log/suricata/eve.json
# Then press / and search for:
# "alert"
# "ET SCAN"
# "ET WEB_ATTACK"
````
### 4. Wireshark Verification
Capture traffic between the client and server VM to correlate Suricata alerts with packet-level activity using relevant filters:
```` bash
icmp
# ping requests/replies
tcp.flags.syn == 1 && tcp.flags.ack == 0
# Nmap SYN Scans
http && ip.dst == 192.168.56.101
# Web requests
ip.addr == 192.168.56.101 || ip.addr == 192.168.56.102
# General lab traffic
tcp.port == 443
# Dropped/Rejected Packets
ip.addr == 192.168.56.101 && tcp
# Correlate the same packets Suricata flagged
````
